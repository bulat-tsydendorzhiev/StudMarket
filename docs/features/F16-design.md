Прочитай существующий проект и папку с исходным frontend-дизайном, которую я предоставил.

Задача: переработать дизайн текущего frontend под визуальный стиль исходника.

## Главное правило

Исходная папка используется **только как визуальный референс**.

Не копируй из неё функциональность, которой нет в нашей спецификации.

Наш функционал имеет приоритет над исходником.

## Backend

**Backend не изменять.**

Не добавляй:

* новые backend endpoints;
* новые таблицы;
* новые поля в БД;
* новые сервисы;
* новую бизнес-логику;
* новые API только ради дизайна.

Используй только существующий API и текущую архитектуру проекта.

## Что нужно изменить

Переработай только frontend:

* layout;
* страницы;
* компоненты;
* стили;
* цвета;
* типографику;
* карточки;
* header;
* sidebar;
* формы;
* profile UI;
* listing UI;
* chat UI;
* адаптивность.

Используй визуальные решения из исходника там, где они подходят нашему функционалу.

Можно переиспользовать frontend-компоненты и CSS из исходника, если это ускоряет работу и не приводит к добавлению лишней функциональности.

## Не добавлять функциональность из исходника

Если в исходном frontend есть функции, которых нет в нашей спецификации, **не реализовывай их**.

Например, не добавлять:

* фильтр по цене;
* сортировку, если её нет в требованиях;
* избранное;
* рейтинги;
* отзывы;
* лайки;
* дополнительные категории;
* дополнительные типы уведомлений;
* дополнительные действия с объявлениями;
* любые другие функции только потому, что они есть в исходнике.

Если элемент исходника одновременно является частью дизайна и содержит лишнюю функциональность — оставить только визуальную часть.

## Наш функционал

Frontend должен поддерживать только существующие требования проекта:

* регистрация;
* вход;
* текущий пользователь;
* профиль;
* аватар и default avatar;
* список объявлений;
* карточка объявления;
* просмотр объявления;
* фотографии объявления;
* теги;
* фильтрация по тегам;
* создание/управление своими объявлениями согласно существующему API;
* автоматическое истечение объявлений через 30 дней;
* чат с продавцом;
* список чатов;
* сообщения;
* unread/read messages;
* индикатор непрочитанных сообщений.

Не расширяй этот список без необходимости.

## Важное правило

Не переписывай работающий frontend без необходимости.

Сначала:

1. Изучи текущий frontend.
2. Изучи исходную папку с дизайном.
3. Сравни существующие страницы и компоненты.
4. Определи, какие визуальные элементы можно перенести.
5. Сохрани текущую бизнес-логику и API.
6. Измени только UI/UX и frontend-структуру там, где это необходимо.

Не меняй API contracts без крайней необходимости.

## Результат

В результате должен получиться наш существующий marketplace с функциональностью из спецификации, но визуально оформленный в стиле исходного frontend.

Исходник не должен определять функциональность приложения.

Наши requirements определяют функциональность.
Исходник определяет только дизайн.

После работы:

* запусти frontend;
* проверь все существующие страницы;
* проверь основные пользовательские сценарии;
* исправь визуальные и runtime ошибки;
* убедись, что backend не был изменён без необходимости.

В конце дай краткий отчёт:

* какие frontend-файлы изменены;
* какие визуальные части перенесены из исходника;
* какие функции намеренно не добавлялись;
* результат проверки.
